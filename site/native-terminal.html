Native terminal spec

Designed for the machine OK Computers already are.

OK Computers expose a terminal, wallet connection, public boards, daily gm posts, direct bot mail, usernames, arbitrary channels, token-owned data, and page publishing. OK Brokers maps the broker-floor game to those primitives without claiming the integration is live today.

The native thesis

OK Brokers is not trying to bolt generic staking utility onto an NFT. The stronger path is to turn the OK Computers command system into a broker-floor game: command in, receipt out.

The public site is the polished explainer. The future native target is a compressed terminal cartridge that can fit inside the OK Computer page/editor flow after the current byte and script limits are verified.

Broker identity

gmpost

Clock-in ritual

Turns the daily gm stream into an attendance mechanic for Terminal Floor shifts.

boardpost

Public receipt

Can announce shift closeouts, rank-ups, or desk unlocks as clearly labeled future actions.

channelwrite

Floor bus

A shared okbrokers channel can model rank movement, desk events, or season chatter.

datawrite

Token-owned data

Can store a compact shift receipt or rank snapshot against a token the wallet owns.

pageedit

Cartridge deploy

Publishes an OK Computer page. This is the future native build target, not a live OK Brokers deployment yet.

Rule 1

Never require transfer

OK Brokers should never ask users to transfer their OK Computer. Early testing should use read-only checks, signatures, board/channel posts, or token-owned data writes only.

Rule 2

Label writes clearly

boardpost, gmpost, channelwrite, datawrite, usernameset, pageedit, and transfer are onchain/network actions. The public demo must not hide that boundary.

Rule 3

Verify editor limits first

Current evidence conflicts: older editor text says 51,200 bytes and no inline scripts; v1.1 notes say 64kb and JavaScript support. The cartridge build waits for live verification.

Rule 4

Keep rewards modeled

BNKR, ETH, USDG, and Stock Desk references remain simulated, gated, or future-only until contracts, audits, legal posture, and approvals exist.
